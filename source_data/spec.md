### 1.2 DATA スキーマ（実測）

```
DATA = { chapters: Chapter[] }
Chapter = { no, title, headingCount, basePages, lessons: Lesson[], ox: Ox[], mc: Mc[] }
Lesson  = { id:"c01-l01", title, sections:string[], html:string, pages: Page[] }
Page    = { id:"c01-l01-p02", title, cont:boolean, html, oxIds:string[] }
Ox      = { id:"c01-ox-01", text(HTML), answer:boolean, explain(HTML), sec:string|null, lesson:"c01-l01" }
Mc      = { id:"c01-mc-01", stem(HTML), items:[{label:"イ",text}], choices:string[5],
            answer:number(1〜5), explain:string[](HTML), tip:string|null }
```

- ID 規則: 章 `c01`、レッスン `c01-l01`、ページ `c01-l01-p01`、○× `c01-ox-01`（元 md の Q 番号）、五肢 `c01-mc-01`（元 md の問番号）。`Logic.chapterOf(id)` は `/^c(\d+)-/` で章番号を取る。
- `Lesson.html` と `Lesson.sections`、`Chapter.headingCount/basePages`、`Ox.sec/lesson` は、ビルド時の検証や集計にだけ使われ、`index.html` は参照しない。`pages[].html` が `lesson.html` の複製になっているので、data.js が膨らんでいる（SAA 版では持たせない）。
- ○× → ページの対応は、元 md の `<!-- sec: 見出し名 -->` タグ → `build.mjs` が見出し名の一致するページの `oxIds` に追加、という手順（一致が無ければエラー）。
- HTML への変換（`renderInline`）: HTML エスケープ → `**x**` を `<b class="key">x</b>` → `【ひっかけ】以降の行末まで` を `<span class="trap">…</span>`（マーカー自体は消える）。箇条書きは入れ子の `<ul><li>`、`####` は `<h4>`、ページの先頭見出しはページタイトルに移して本文から除く。
- ページ分割: `####` 1つが1ページ（`###` 2〜3 は `####` ごと）。1800 字（プレーン文字数）超は最上位箇条書きの境目で「（続き）」ページに分ける。レッスン = 4,000 字以内に束ねた連続小項目。

### 1.4 進捗 JSON スキーマ（version 1）

```json
{
  "version": 1,
  "position": null,
  "lessonsDone": ["c01-l01"],
  "quizResults": { "c01-ox-01": { "correct": true, "ts": 1700000000000 } },
  "wrongLog": ["c01-mc-03"],
  "chapterTest": { "1": { "score": 0.8, "passed": true } },
  "reports": [{ "id": "c01-ox-01", "memo": "…", "ts": 1700000000000 }],
  "settings": { "passRate": 0.7, "unlockAll": false }
}
```

- `position`: `null` または `{ch:number, lessonId:string, page?:非負整数}`。
- `chapterTest[章].score` は 0〜1 の正答率。UI は `Math.round(score*100)%` で表示。合格済みの章で不合格になっても `passed` は true のまま、`score` は最高値を保つ。
- `validate` は型の厳密検査で、1項目でも不正なら全体を拒否する。

### 1.5 UI の挙動（SAA 版でも維持するもの）

- 1画面1ページ。ページに紐づく ○× があれば「次へ」で確認クイズ（1問ごと即採点＋解説、「本文を読み返す」、「もう一度挑戦」）。6ページ進むごとに休憩画面。位置はページ単位で保存。
- レッスン最終ページを終えるとレッスン完了。章のレッスン完了後に章末テスト（その章の mc 全問、正答率 70% 以上で合格、設定で 10〜100%）。合格で次章が開く。
- 間違えた問題が `wrongLog` に溜まり「復習」メニューで再出題（正解で除外）。
- 「間違いをメモ」（`window.prompt`、`reports` に保存、書き出し可）。進捗 JSON の書き出し/読み込み/全消去、「全章を開放」、localStorage 不可時の警告。

| 項目 | gaimuin | 問題点 | SAA 版 |
|---|---|---|---|
| `answer` | `number`（1〜5） | 複数正解を表せない | `string[]`（`["B"]`、`["A","C"]`。文字は `A`〜`E`、昇順、重複なし） |
| 選択数の指定 | なし | 「2つ選べ」を UI が判断できない | `selectCount`（正解数と一致。1 または 2。将来の3つ選択も可） |
| 選択肢数 | 5固定 | 単一は4択 | `choices` は 4〜6 個。選択肢文字は添字から決める（`'ABCDEF'[i]`）。**選択肢文に `A.` を含めない** |
| 採点 | `ans === q.answer` | 集合の一致が必要 | 集合の完全一致（順序不問、部分点なし、過不足は不正解） |
| 解説 | `explain: string[]`（イ〜ニの解説）＋`tip` | 選択肢ごとの ○/× を機械で扱えない | `choiceExplain:[{ok, text}]`（添字は `choices` と1対1）＋`tip`。`ok` が `answer` に含まれる文字と一致することを検証できる |
| 組合せ型 `items` | イロハニ | SAA は無い | 廃止 |
| ドメイン | なし | 配点配分に必要 | `domain: 1|2|3|4` |
| 出典 | なし | 検証に必要 | `src`（元 md の問の先頭行番号） |

回答値（UI・進捗・採点の入力）は **常に文字列配列** `["B"]` / `["A","C"]` とする。`gradeMc` は互換のため文字列 `"B"` も受け取り、内部で `["B"]` に正規化する。

### 3.2 選択 UI（複数選択）

- 問題文に「（2つ選べ）」のバッジを表示。選択肢ボタンはトグル式で、`selectCount` 個を超える選択は不可（超えたら最後のクリックを無視し、メッセージを出す）。
- 「回答する」ボタンはちょうど `selectCount` 個選んだときだけ有効。単一選択は従来どおり1クリックで確定（総仕上げでは確定せず選択のみ）。
- 結果表示: 正解の選択肢は緑、選んだが誤りは赤、選ばなかった正解は緑の枠で「選び漏れ」を表示。

### 5.4 `data-chNN.js` の整形ルール（800行以内にするため）

- ページは1ページ1ブロック（`id`・`title`・`html`・`oxIds`・`src` を各1行。`html` は1行の文字列）。長い `html` は途中で改行しない。
- ox は1問を `{ id, text, answer, explain, src }` として、5行程度。
- mc は `choices` を1行1要素、`choiceExplain` を1行1要素で書く（1問 約20行）。
- 目安: 章あたり ページ約25＋ox約28＋mc約16 → 約600〜700行。**第10章は mc 26問のため `data-ch10.js`（章メタ・レッスン・ページ）と `data-ch10b.js`（mc 追記）に分ける**（`data-ch10b.js` は `window.DATA.chapters.find(c => c.no === 10).mc.push(…)`）。他の章でも800行を超える場合のみ同様に `data-chNNb.js` に分ける。
- ファイル名の辞書順（`data-ch10.js` < `data-ch10b.js`）が Node 側の読み込み順になる。ブラウザ側は `index.html` の `<script>` 順。

### 6.2 レッスンとページの作り方

- **ページ**: `####` 1つを1ページにする。ページタイトルは `####` の見出し文字列そのまま（`**`・`【】`などはそのまま残さず、プレーンテキストにする）。本文の先頭は見出しの次の行から。
  - 1ページのプレーン文字数（タグを除いた文字数）が 1,800 を超える場合は、最上位の箇条書きの境目で「（続き）」ページ（`cont:true`、タイトルは `見出し（続き）`）に分ける。**1,800〜2,000 字までは警告、2,000 字超はエラー**。
  - 400 字未満のページは、直後の `####` と統合してもよい（統合したページはページ内に `<h4>` で小見出しを残し、タイトルは「見出し1・見出し2」とする）。統合後も 1,800 字を超えない。
  - §2（試験での出方）は1ページ（【頻出】【ひっかけ】コツを順に）。1,800字超なら最上位箇条書きの境目で2ページに分ける。§3（暗記すべき数字）は1ページ（超えたら分割）。ページタイトルは `試験での出方`、`暗記すべき数字・制限`（分割時は「（続き）」）。
- **レッスン**: §1 の連続するページを、プレーン文字数 約5,000 字を上限に束ねる（`####` の途中では区切らない。1レッスンは 4〜12ページ）。**章の最後のレッスン**は §2＋§3 のページで構成する（レッスンタイトルは「試験での出方と暗記数字」）。レッスンタイトルは、含まれる `####` から主題が分かる名前を付ける（例 `IAMの基本（ユーザー・グループ・ロール・ポリシー）`）。
  - 章あたり 3〜4 レッスン＋最終レッスン（目安 4）。
- **○×のページへの対応付け**: 各 ox を、内容を最もよく扱うページの `oxIds` に入れる（`sec` の代わり）。同じ章の中で、1つの ox はちょうど1ページに属する。迷う場合は、その主題を含むレッスンの最後のページか、数字の問題なら §3 のページ。第1〜9章では、**どのレッスンにも ox が1問以上**あるようにする。1ページに ox が 6問を超える場合は、近い別ページに分散する。
- **章末テスト・総仕上げ用の mc**: 章の §5 の全問を `mc` に入れる（レッスン内クイズには出さない）。

### 6.3 変換ルール

**原則（最重要）**

1. **逐語転記**: 本文・問題文・選択肢・解説の語句は元 md のとおりにする。要約・言い換え・追加・順序の入れ替えはしない。許される変更は次の4つだけ: ① インライン記法の HTML 化（下記）、② `A：○ ` のような接頭辞の除去と `ok` への変換、③ `【単一選択】` などの問題種別タグを `selectCount` / `domain` に変換して stem から除く、④ 問題文の続き行を `<br>` で連結。
2. **元データにない事実を足さない**。解説が薄くても補わない。
3. **元データの誤りに気づいても正さない**。`docs/notes/chNN.md` に記録する（下記）。

**インライン変換**（`renderInline` と同順）

| 元 | 変換後 |
|---|---|
| `<!-- … -->` | 除去 |
| `&` `<` `>` `"` | `&amp;` `&lt;` `&gt;` `&quot;`（この順。先に実行） |
| `**x**` | `<b class="key">x</b>` |
| `【ひっかけ】…（行末まで）` | `<span class="trap"><span class="badge b-trap">ひっかけ</span>…</span>`（gaimuin はマーカーを消すが、SAA 版はバッジとして残す） |
| `【頻出】` | `<span class="badge b-freq">頻出</span>`（その位置のまま） |
| `【比較】` | `<span class="badge b-cmp">比較</span>` |
| `【注】` `【注記】` | `<span class="badge b-note">注</span>` |
| `` `x` `` | `<code>x</code>` |
| その他の `【…】` | そのまま |

**ブロック変換**

- 入れ子の箇条書き → `<ul><li>…<ul><li>…</li></ul></li></ul>`（入れ子は2スペースで1階層）。箇条書きでない行 → `<p>`。ページ内の小見出し（統合時のみ） → `<h4>`。
- 許可するタグ: `ul li p b span code br h4`。属性は `class` のみで、値は `key trap badge b-freq b-cmp b-trap b-note`。`<script>`、`<style>`、`on*=` は禁止。
- `Ox.text` / `Ox.explain` / `Mc.stem` / `Mc.choices` / `Mc.choiceExplain.text` / `Mc.tip`: すべて `renderInline` を適用した文字列（ブロックタグは使わない。`stem` の改行は `<br>`）。

**ox**: `答え：○` → `true`、`答え：×` → `false`。`explain` は `解説：` の後ろ。`src` は `- Qn.` の行番号。

**mc**

- 種別: `【単一選択】` → `selectCount:1`、`【複数選択（2つ選択）】` → `selectCount:2`。`answer` は `答え：**B**`、`**A、C**`、`**A と C**` から文字を取り出し昇順にした配列。`selectCount === answer.length`。
- `choices` は `- A. …` の本文のみ（接頭辞なし）。`choiceExplain[i]` は `答えと解説` 内の `A：○ …` の `○`/`×` を `ok` に、残りを `text` にする。`ok` が `answer` と一致していること。
- `tip` は `解き方のコツ：` の後ろ。
- `domain`: 第1〜9章は、問題が主に問う観点で決める。**セキュリティ・暗号化・アクセス制御・監査 → 1、可用性・耐障害性・DR・疎結合・スケーリング → 2、性能（レイテンシ・スループット・キャッシュ・ストレージ/DB の選定）→ 3、コスト（「最もコスト効率」「購入オプション」「ライフサイクル」）→ 4**。迷ったら問題文の最後の要件の修飾語（最もセキュア／最も可用性が高い／最もパフォーマンス／最もコスト効率）で決める。章ごとの目安: 第1・2章 → 1、第8章 → 2、第9章 → 4。第3〜7章は内容で判断する。判断に迷った問題は `docs/notes/chNN.md` の「domain 判断」に ID と理由を書く。第10章は `【セキュア】`=1、`【弾力性】`=2、`【高性能】`=3、`【コスト】`=4 に変換し、タグ文字列は stem から除く。

**疑義メモ**（`docs/notes/chNN.md`。各担当が章ごとに作る）

```markdown
# 第N章 疑義メモ
## 元データの疑義（正さずそのまま転記した箇所）
| 行 | 該当文（抜粋） | 疑義（何が古い/不正確/矛盾の可能性か） | 確度（高/中/低） |
## domain 判断
| id | 選んだ domain | 理由 |
## 構成の判断（ページ統合・分割、ox の対応付けで迷ったもの）
```

疑義は「サービス仕様の最新版と異なる可能性」「章内・章間の数字の不一致」「誤字・用語の不統一」など。確度が低いものは書かない。事実確認は §9 の後続作業とし、転記時には外部検索で補わない。

### 6.4 第10章（担当 E）の特記

- §1（逆引き）: `####` 8つ。各 `####` は 20〜30項目の1行リスト。1,800字を超えるカテゴリは分割する（`（続き）`）。レッスンは約2つ。
- §2（紛らわしいサービスの比較）: `####` が無い。【比較】で始まる54項目（各項目に子箇条書き）を、連続する項目を束ねて1ページ約1,800字以内にする。ページタイトルは含まれる比較の主題（例 `SQS/SNS/EventBridge ほか`）。レッスンは約2つ。
- §3（修飾語）: `####` 11個。各 250字前後と短いので、連続する `####` を統合してよい（1ページ約1,500字以内、`<h4>` で小見出しを残す）。レッスンは1つ。
- §4（試験直前の数字まとめ）: `####` 5個。1〜2ページ（統合可）。レッスンは §3 と同じでもよい。
- §5（総仕上げ模擬問題）: 26問を `mc` に（`c10-mc-01`〜`26`）。stem の `- 要件：…` のような続き行は `<br>` で連結。章末テスト（第10章）として出題され、総仕上げの問題プールにも入る。
- ox は無い（`ox: []`、どのページも `oxIds: []`）。「どのレッスンにも ox」の検査は第10章のみ免除する。

### 6.5 担当への共通の作業手順

1. 自分の章の元 md の範囲を読み、`####` の一覧と文字量を確認する。
2. 章ごとに `app/data-chNN.js` を、レッスン単位で追記しながら書く（一度に全部を書かず、レッスン→ox→mc の順で）。§5.4 の整形ルールを守る。
3. `node tools/validate.mjs --chapter N`（§7.1）と `node tools/crosscheck.mjs --chapter N`（§7.2）を実行し、**エラー0**になるまで直す。警告は `docs/notes/chNN.md` の「構成の判断」に理由を書く。
4. `docs/notes/chNN.md` に疑義メモを書く。
5. 担当範囲外のファイルは変更しない。

## 7. 検証方法

### 7.1 スキーマ検証 `tools/validate.mjs`

- 公開: `validateData(data, opts?) → {errors:string[], warnings:string[]}`（`opts.chapter` で1章だけ検証、`opts.full` で全体検証）。CLI: `node tools/validate.mjs [--chapter N] [--full]`、エラーがあれば exit 1。
- データの読み込み: `tools/load-data.mjs` の `loadData(dir='app')` が、`app/data-ch*.js` を辞書順に1ファイルずつ `vm.runInNewContext(code, sandbox)` で実行する。`sandbox = {window: {}}` を全ファイルで共有し、`sandbox.window.DATA` を返す（ブラウザと同じコードが Node で動く。ビルド工程は不要）。ファイルが `window` 以外に触れたらエラー。
- 検査項目:

| 範囲 | エラー | 警告 |
|---|---|---|
| 章 | `no` が 1〜10 の整数・重複なし。`title`・`domainNote` が非空文字列。`src` が `[from,to]`（元 md の範囲内）。`lessons` が空でない配列。`ox`・`mc` が配列 | レッスン数が 2〜8 の外 |
| レッスン | `id` が `^cNN-lMM$`（NN=章番号）で 01 から連番。`title` 非空。`pages` が1つ以上 | ページ数が 3〜14 の外 |
| ページ | `id` が `^cNN-lMM-pKK$` で連番。`title` 非空。`html` 非空。許可タグ・許可クラスのみで、タグが対応している（スタックで検査）。プレーン文字数 ≤ 2,000。`oxIds` が同じ章の ox を指す。`src` が `[from,to]` で、章の `src` 内 | プレーン文字数が 1,800 超。400 字未満のページ（統合の検討） |
| ox | `id` が `^cNN-ox-\d\d$`。`text`・`explain` 非空。`answer` が boolean。ちょうど1ページの `oxIds` に属する。`src` が整数 | 1ページに6問超。ox が0問のレッスン（第10章を除く） |
| mc | `id` が `^cNN-mc-\d\d$`。`stem` 非空。`choices` が 4〜6個の非空文字列で、先頭が `A.`/`B.` の形でない。`answer` が文字配列（昇順・重複なし・`choices` の範囲内）。`selectCount === answer.length` かつ 1〜3。`domain` が 1〜4。`choiceExplain` の長さが `choices` と同じで、各 `{ok:boolean, text:非空}`、`ok === answer.includes(文字)`。`tip` 非空。HTML は許可タグのみ。`src` が整数 | 複数選択（`selectCount≥2`）なのに選択肢が5個未満。単一選択で選択肢が4個でない |
| 全体（`--full`） | ID の重複なし（章をまたいで）。章が 1〜10 すべてある。**各 domain の mc 数が、総仕上げの配分（65問 19/17/16/13＋採点対象外の再配分を考慮して）以上**（目安: 各 domain 25 問以上） | 総ページ数が 200〜320 の外。`data-chNN.js` が800行超 |

### 7.2 元 md との突き合わせ `tools/crosscheck.mjs`

`validate.mjs` は書式の検査にとどまる。逐語転記の原則（§6.3）は、元 md を別の正規表現で読み直して比較することで検証する。変換ロジックは `validate.mjs` と共有しない。

- 公開: `crosscheck(data, mdText, opts?) → {errors, warnings}`、CLI: `node tools/crosscheck.mjs [--chapter N]`。
- 検査項目（エラー）:
  1. 章ごとの `Q` の数、`問` の数（単一/複数）が元 md と一致（合計 ox 246、mc 171、単一138、複数33）。第10章の ox は0、mc は26。
  2. 元 md の各 `Qn` に対応する id（`cNN-ox-nn`）が存在し、`answer` が一致。各 `問n` の `answer` の文字集合、`selectCount`（種別タグ）、選択肢数が一致。`src` が元 md のその問の先頭行と一致。
  3. **テキストの一致**: データの HTML をプレーン化（タグ除去、エンティティ復元、`<br>` → 空白、バッジ文言の除去）し、元 md 側を正規化（`**`・バッククォート・マーカー文言・先頭の `A：○ ` 等・種別タグの除去、空白の圧縮）したものと完全一致。対象は ox の `text`/`explain`、mc の `stem`/各 `choices`/各 `choiceExplain.text`/`tip`。
  4. **ページの網羅性**: 章ごとに、`pages[].src` の範囲が §1〜§3 の本文（`####` の見出し行は除く。空行は除く）を重複・欠落なく覆う。各ページのプレーン化した `html` が、その `src` 範囲の元 md の行（箇条書きの記号と `**`・マーカー・空白を除く）を連結したものと一致する。
  5. 元 md の数字トークン（`\d[\d,.]*` と単位）が、同じ章のページにすべて含まれる（3 と 4 が満たされれば自動的に満たされる冗長検査）。
- 警告: ox が属するページと、ox のテキストの共通語がほとんど無い（対応付けの疑い）。

## 付録 A. 機械変換方式（推奨の代替案）

元 md が極めて規則的（§2、417問すべてで例外0）なので、`tools/convert.mjs` で `docs/saa-c03.md` から `app/data-chNN.js` を直接生成できる。変換器が行うこと: `####` → ページ、1,800字超の分割、レッスンの束ね（約5,000字）、`renderInline`、ox・mc の解析（`domain` は第10章のタグ以外は後述の対応表から）。

人（またはサブエージェント）の作業は、次の2つのサイドカー JSON に絞れる。

- `docs/map/chNN.json`: `{ "ox": { "01": "ページ見出し", … }, "mcDomain": { "01": 1, … }, "lessonTitles": [ … ] }`。ox のページ対応付けと mc の `domain`、レッスンタイトルだけ。
- `docs/notes/chNN.md`: 疑義メモ（§6.3）。

利点: 逐語転記が機械的に保証される（`crosscheck.mjs` は変換器と独立なので検証も有効）。出力トークン量が大幅に減る（担当あたり約70K トークン → 約5K）。ページやレッスンの構成が章をまたいで揃う。欠点: 変換器の実装とテスト（約300行）が先に必要。gaimuin の `parse.mjs`/`build.mjs` を流用できる。

どちらの方式でも、`data-chNN.js` のスキーマ（§4）、検証（§7）、アプリ側（§5）は同じ。本書の §6 の分担表は、方式 A でも「担当ごとの章の割り当て」としてそのまま使える。
